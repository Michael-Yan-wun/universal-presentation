# Universal Presentation · AIWin 10 週年

**From Edge to Agent — 十年經驗，積累成功。**

慧穩科技十週年活動使用的互動式 3D 演講網站。以「生命體的成長」串起感知、專案學習、知識與行動；以積木呈現產品能力，最後揭曉整合影像與數據、可模組化擴充的 **WinEdge**。

- [正式展示網站](https://winedge-anniversary-experience.yanwun1214.chatgpt.site/)
- 使用情境：桌面、16:9 投影、講者手動推進。
- 技術：原生 HTML / CSS / JavaScript、Three.js **0.180.0**、本機圖片與 H.264 MP4。
- 執行不需要 npm 安裝、編譯、API Key、資料庫或後端服務；所需的 Three.js 與展示素材皆已收錄。

本倉庫保存目前的 AIWin 演講版本。修改內容與動畫需編輯原始碼，目前沒有通用簡報編輯器或即時 AI 訓練功能。

## NumOps / WinChat 硬體配置

產品最後一幕保留積木融合，再帶出各自的運算硬體；沿用原本上一段／下一段，不增加講解頁數。

- **NumOps：APLEX AVS-530**。無風扇工業電腦，銀色散熱鰭片、前面板 LAN／USB／COM 與電源端子。部署圖同步標示 WinEdge-N 搭載 AVS-530。
- **WinChat：兩種部署選擇**。小團隊使用 NVIDIA DGX Spark；大型部署呈現搭載 RTX PRO 6000 的工作站。以中央 WinChat 積木、共用展台與兩台主機形成完整構圖；Spark 使用抬高展座，兩種部署名稱對齊各自主機，訊號沿共同底座與背架流動。
- `dist/product-hardware.js` 提供原生 Three.js 幾何模型、風扇與訊號動畫；`product-journey.js` 管理融合、返回和重播。模型不依賴外部貼圖或 CDN。
- 硬體搭配依本次產品規劃；工作站為原創剖面示意，RTX PRO 6000 是內部顯示卡，未宣稱特定 OEM 主機、模型容量、並行人數或測試效能。
- 官方外觀參考記錄於 [NumOps 素材來源](dist/assets/numops/CREDITS.md#avs-530-hardware) 與 [WinChat 素材來源](dist/assets/winchat/CREDITS.md#hardware-deployment)。
- 減少動態效果時直接顯示完整配置，停止風扇與光點。驗證包含 1920 × 1080／1280 × 720、返回後重播融合、離場清理與資源釋放。

## 快速啟動

需求：Git、Python 3，以及支援 WebGL 2 的桌面瀏覽器。

```sh
git clone https://github.com/Michael-Yan-wun/universal-presentation.git
cd universal-presentation
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

開啟 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。在終端按 `Ctrl+C` 停止伺服器。

請透過 HTTP 開啟；直接雙擊 `index.html` 的 `file://` 方式無法可靠載入 ES Modules 與素材。若 8765 已被使用，可改成 8766 等其他連接埠，並使用對應網址。

> **`dist/` 就是此專案的原始網站檔案，也同時是發布目錄。** 它不是自動生成的建置產物；修改後需要保留並提交。

### AIWinOps：從實戰經驗，到視覺模型

章節入口：[AIWinOps](http://127.0.0.1:8765/?v=keynote-flow-1#decade)。城堡入口：[智慧全貌](http://127.0.0.1:8765/?v=keynote-flow-1#castle)。新版維持暖銅色、深色舞台、大型 DOM 文字及清晰 SVG 圖解。

1. 進入 `#decade` 直接組裝五個案例積木，移除 VISION 字幕及重複的三類能力總覽。
2. 下一步讓第一塊案例移至前景（約 0.72 秒），開啟大型影片與右側解說。
3. 每案影片下方同時展示「相機 → WinEdge-V ＋ Edge 硬體 → 現場結果」。下一步直接切換下一案，不再另翻硬體頁。
4. 五案完成後，依序展示 **5 個手動步驟**：專案整理、AI 輔助標註、四種視覺任務、訓練與模型分析、驗證與部署回饋。
5. 最後全部專案積木形成龍捲風融合（約 6.8 秒），揭曉 AIWinOps；停留至講者推進到 NumOps。

影片預設靜音循環，保留播放與拖曳控制，離場即停止。若瀏覽器阻擋自動播放，可按播放器播放。`Esc` 回到案例積木，前後箭頭與鍵盤可逐案切換。從產品返回會回到最後的驗證與回饋；跨章返回 AIWinOps 則停在產品揭曉，避免整輪重播。

官方資料集、標註、訓練曲線、驗證介面完整保留。訓練動畫與官方分析畫面整合於同一幕；驗證與 WinEdge-V 部署回饋也合為一幕。任務畫面包含 Wafer Map 分類、瓶蓋偵測、齒列分割技術展示與網布正常樣本。沒有新增客戶效益數字；官方曲線為示範資料，硬體與資料流為概念圖解。

講稿見 [AIWinOps 與夥伴頁](docs/AIWINOPS-ECOSYSTEM-KEYNOTE.md)，來源見 [官方素材註記](dist/assets/aiwinops/CREDITS.md)。實作：`aiwinops-keynote.js` / `.css`、`history-wall.js`、`history-ui.js`。3D 場景在影片及學習圖解展示時停止繪製，減少 GPU 負擔。測試涵蓋五案完成條件、五步手動進度、返回／跨章返回及重入重設。

### NumOps：從數據學習，到現場決策

開啟 [NumOps 新版](http://127.0.0.1:8765/?v=waterops-partnership-1#analytics)。講稿見 [NUMOPS-KEYNOTE.md](docs/NUMOPS-KEYNOTE.md)，來源見 [素材與內容註記](dist/assets/numops/CREDITS.md)。NumOps 初版在 `codex/numops-keynote` 開發；WaterOps 合作實證頁接續在 `codex/aiwinops-ecosystem` 更新，尚未發布正式 Sites。

以數據光帶開場，承接生命體「感知之後，學習規律」的成長故事。三段共 **8 個手動步驟**，建議講述約 **7–8 分鐘**（含開場與揭曉）；每幕停留至講者前進，不自動換頁。

| 段落 | 展示順序 |
| --- | --- |
| 讀懂數據 | 官方資料預處理（結合設備、時間與目標） → 分類、異常、回歸、時序與分群 |
| 學會預測 | AutoML 動畫與官方模型建立同頁 → 官方模型分析 → AutoML ＋ 專家系統 |
| 回到現場 | 智慧烤箱案例 → GSD × AIWin WaterOps 合作與實證（同一頁） → WinEdge-N 硬體部署 |
| 產品揭曉 | 經驗模組旋轉匯聚 → NumOps 產品積木 → WinChat |

WaterOps 將合作分工、案例證據與水務流程整合為一頁：GSD 水處理工程與操作經驗 × AIWin 數據 AutoML。以官方頒獎照片搭配矽品中科廠硼廢水智能精準加藥案例，引用 WaterOps 2026-06-05 公布的 **BaCl₂ 用量下降 45%、H₂O₂ 下降 24%**，並標示矽品獲 2026 環境部淨水永續獎。數字僅指該案例個別藥劑用量，不代表所有客戶或總成本降幅。底部水質資料 → WaterOps → 現場調控 → 持續優化為流程動畫，手動下一步直接接模型部署；不會連線客戶平台或操作現場。

全程只使用既有前後控制與鍵盤。返回逐步回溯，重新進入重設；三段完成後才揭曉 NumOps。細節使用獨立資料流與大型官方畫面，無重複概念總結。支援減少動態效果設定，測試以桌面投影為主。

實作：`numops-script.js` 定義步驟與提詞；`numops-keynote.js` / `.css` 管理圖解、轉場與版面；`waterops-keynote.js` / `.css` 管理單頁合作實證；`product-journey.js` 共用完成條件與 3D 揭曉。驗證：`node --test tests/*.test.mjs`，涵蓋 NumOps 與 WinChat。

### WinChat：Agent 統籌 RAG 與 SKILL（約 10–12 分鐘）

WinChat 開場保留大型企業大腦，**Agent 是統籌者**；RAG 提供知識，SKILL 提供工作方法與工具能力，再進入實際應用。

| 角色 | 對觀眾的說法 | 內容 |
| --- | --- | --- |
| RAG | 找得到依據 | VLM 圖像理解、文字理解、知識索引、檢索與來源引用 |
| SKILL | 有方法，也有工具 | 可重複使用的工作步驟、工具使用與輸出要求 |
| Agent | 把工作串起來 | 理解目標、規劃、調用知識與能力、整理及檢視結果 |
| 應用與成果 | 能夠交付工作 | 客服維修、新人培訓、現場巡檢 |

預覽：[WinChat 章節](http://127.0.0.1:8765/?v=winchat-launch-1#chat)。講述稿：[WinChat 舞台講述稿](docs/WINCHAT-KEYNOTE.md)。建議 **10–12 分鐘**是人工講述配速，沒有自動翻頁計時。

- **RAG，5 步：** VLM 架構圖理解 → 多模態索引資料流 → 官方知識庫 → 檢索資料流 → 官方問答與來源追溯。
- **SKILL，3 步：** 工作方法手冊 → Agent 調用 SKILL 與工具 → 官方工具管理。
- **應用，4 步：** 工作目標 → 官方戰情室 → 現場巡檢摘要 → LINE／警示設備／報告輸出，下一步直接進入 WinChat 揭曉。
- **收尾，1 幕：** 大腦聚光凝結 → WinChat 積木，再接回協作成形。

主題列表、大腦標籤與內頁沒有額外按鈕、跳轉箭頭或操作教學。用左右方向鍵、Page Up/Down、空白鍵或全站底部前後步驟控制；每幕可停留，WinChat 不接受滾輪翻頁。三段主題完成後才融合。

首次進入主題時保留當下大腦，沿對應區域平移放大，約 1.35 秒接入內容；後續細節及跨主題直接平移銜接，只有返回總覽才拉遠。移除短暫替換的過渡標題。**大腦只用在總覽、首次進入／返回總覽及收尾；細節使用資料流與示意圖。** 每張主要官網介面圖只展示一次，不用連續微小放大填充步驟。圖解明確區分輸入、處理、輸出，連線光點呈現移動方向，每一步仍由講者推進。

官方知識庫、問答、工具管理、戰情室及工作區圖片保留原檔，來源見 [`CREDITS.md`](dist/assets/winchat/CREDITS.md)。產品畫面為展示截圖；VLM、工具調用、現場巡檢摘要與應用成果為演講示意，沒有連線正式設備或使用客戶即時資料。具體工具依實際部署配置。SKILL 工作方法及 VLM 參與 RAG 的定位依使用者產品補充，不宣稱相容特定開放檔案格式。

實作檔案：

- `winchat-script.js`：12 個手動步驟、順序、講述時間與隱藏提詞。
- `winchat-story.js` / `winchat-brain.js`：Agent 大腦總覽與收尾。
