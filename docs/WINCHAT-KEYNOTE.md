# WinChat 舞台講述稿與按壓節奏

本段建議約 **12 分 35 秒**，可依現場停留伸縮；程式沒有自動翻頁計時。面向 150 人桌面投影，以完整舞台、大字與產品畫面為主。

預覽：<http://127.0.0.1:8765/?v=winchat-brain-1#chat>

## 操作

- 用右方向鍵、Page Down、空白鍵或畫面右下的主題動作按鈕推進。
- 左方向鍵／Page Up 回到上一個揭曉步驟，包括同一張圖的放大前後。
- 每一幕可無限停留。VLM、任務拆解、技能連結及應用成果都等你按下才展開。
- 官網介面是本地展示素材；按下只移動展示鏡頭，不會呼叫產品或改動正式系統。
- WinChat 不接受滾輪翻頁，避免講述或觸控板操作時誤跳。
- 轉場深入大腦主題時暫停推進；三個主題的最後一步都展示過，才能融合。
- 建議使用簡報遙控器的右方向鍵或 Page Down。講稿在這份文件，觀眾畫面不顯示操作教學或時間。

## 節奏總覽

| 區段 | 建議時間 | 舞台變化 |
| --- | ---: | --- |
| 接續生命體：企業開始有記憶與思考 | 0:30 | 大型企業大腦與三組神經能力 |
| RAG：圖文理解、企業知識與引用 | 4:15 | 掃圖 → 圖文合流 → 三幅官網畫面 → 引用放大 |
| Agent：由目標到現場工作 | 3:00 | 工作目標 → 拆解任務 → 彙整 → 戰情室 → Copilot |
| Skill：能力組合與三種應用 | 3:40 | 神經技能 → 連結 → 工具介面 → 三種應用成果 |
| 融合、WinChat 揭曉與工作區 | 1:10 | 大腦聚光凝結 → WinChat 積木 → 官方工作區 |
| **合計** | **12:35** | 18 個主題步驟，加開場與產品收尾 |

這是講述配速建議，並非影片固定片長。各步驟的秒數與提詞亦存在 `dist/winchat-script.js`，方便日後調整。

## 一、從感知與學習，走到記憶（0:30）

「前面我們讓這個生命體學會看見、感受，也在一個個專案裡累積經驗。但如果經驗只停在某個人的腦中、某份文件裡，別人需要的時候仍然找不到，這份能力就還沒有真正留下來。接下來，我們希望企業有自己的記憶，能理解問題，也能把知識用到工作裡。」

停一下，讓觀眾看見 RAG、Agent、Skill 三組神經能力，再進入 RAG。

## 二、RAG：企業的知識，不只在文字裡（4:15）

### 1. 先看文件，不急著解釋技術（0:35）

展示大幅維修手冊。「實際現場的知識，不只是一段文字。工程師會看設備圖、零件位置、流程圖和操作說明。如果只把文字抽出來，圖和說明之間的關係可能就不見了。」

指向圖中的部件，提出問題：如果我要查這個部件，系統能不能把圖和知識連起來？

### 2. 按「讓 VLM 看懂圖像」（0:40）

等掃描與標籤完成，再說明 VLM 的讀圖角色。「我們在 RAG 的過程中加入圖像理解，讓圖片、圖表與頁面內容，也能參與知識的建立。」

此圖為概念示意，不宣稱這是一段實測辨識影片。

### 3. 按「連起文字與圖像」（0:45）

VLM 與 LLM 兩路出現，接著看到 Embedding。「VLM 幫我們看懂圖，LLM 理解文字與脈絡，Embedding 則讓內容成為可以檢索的表示。當人問問題時，我們要找回的是相關知識，也包括它來自哪裡。」

不要把三個名詞連續念過；各停一下，對應到畫面上的一個角色。

### 4. 企業知識庫實際畫面（0:35）

指向多個知識庫與產品手冊。「這些知識可以依部門、產品或任務整理。剛才看到的 WinEdge、NumOps、AIWinOps，自己的手冊與經驗也能成為企業知識的一部分。」

### 5. 知識檢索設定（0:35）

畫面聚焦 Vector、Hybrid、GraphRAG。「找知識有不同方式：語意相近、關鍵字精準匹配，或是知識之間的關係。企業可以依資料特性選用適合的組合。」

不需要向非技術觀眾講索引演算法；重點是知識的整理與查找可以配置。

### 6–7. 問答與引用（0:30 + 0:35）

先展示官網問答，再按「展開引用來源」讓鏡頭推近。「答案出來之後，我們還需要知道：依據是哪一份文件？能不能回去查？這樣才能讓企業知識被查核、被補充，而不是只得到一段看起來合理的文字。」

官網範例含法規問題，本段只介紹介面與引用機制，不逐條解說法規內容。

轉折：「但有時候，我們想要的不是一句答案，而是一份工作。」

## 三、Agent：從一個目標，走到工作結果（3:00）

### 1. 先提出工作目標（0:30）

只顯示「今天的現場，哪些地方需要留意？」。「這個問題可能要看設備狀況、查歷史紀錄，再對照相關 SOP。它不會只存在一份文件裡。」

### 2. 按「展開任務步驟」（0:40）

三個步驟依序進場。「查知識、連資料、做分析。Agent 的價值，是把問題需要的知識與工具串在一起，協助完成這個目標。」

### 3. 按「彙整工作結果」（0:35）

讓摘要出現。「最後，把零散訊息整理成能讓人判讀的內容：今天發生了什麼、需要注意什麼、有哪些規範可以參考。」

避免把這一幕說成自動控制設備；它呈現的是工作協作與資訊整理。

### 4–5. 戰情室全景與 Copilot（0:40 + 0:35）

先看大型官方戰情室：指標、趨勢、事件，再按「聚焦 AI Copilot」。「企業原本就有很多資料。我們希望從『看見數字』，更進一步到『掌握工作脈絡』。在巡檢情境裡，這能協助人員把注意力放在值得追查的變化。」

所有數字是官網展示截圖，不是現場即時資料或新客戶成效。

## 四、Skill：把專業變成可以組合的能力（3:40）

### 1–2. 神經技能與連結（0:30 + 0:40）

先讓三個能力節點分開。「企業有不同專業：知識檢索、資料分析、工作彙整。我們希望它們能像積木，依任務自由組合。」

按「連起大腦的技能」，等神經連線亮起。「同一個 Agent，可以依工作需要使用對應能力。這也讓前面各個產品累積的專業，有機會在同一個工作流程中一起發揮。」

### 3–4. 官方技能管理與放大（0:35 + 0:35）

展示實際工具包，指出知識庫與系統工具，再按下聚焦。「這些能力可以被管理。哪些工具開啟、可使用哪些資源、怎麼配置參數，都是企業需要掌握的部分。」

畫面只是公開介面的展示，不會真的更改工具啟用狀態。

### 5–6. 三種應用與成果（0:35 + 0:45）

先留下三個問題，逐一講述：

- **客服維修：** 拿到一張圖或產品問題，如何找到圖解、文件與維修知識？
- **新人培訓：** 第一次面對工作，如何查流程、問規範，把前人的經驗接起來？
- **現場巡檢：** 今天的資料與紀錄，如何整理成值得關注的事項？

按「展開三種工作成果」後收束：「同樣是 WinChat，不同的工作，會組合不同的知識、資料與工具。讓企業留下的經驗，進入每一天的工作。」

## 五、融合與收尾（1:10）

按「融合為 WinChat」，讓大腦的神經訊號聚光、收攏，再凝結成 WinChat 積木。先停留看產品，再說：

「RAG 是企業的記憶，Agent 把目標串成工作，Skill 讓專業可以組合。這三種能力，在此刻凝聚成 WinChat 積木。」

進入官方工作區，用 RAG／Agent 模式收尾：

「我們希望留下的不只是一份答案，而是能持續使用的企業能力。從感知、學習，到記憶與協作，這些積木現在可以一起工作。」

下一步接回原本的「協作成形」。
